# Proyecto 6 — Mapeo ISO/IEC 27001:2022

## Objetivo

Este documento relaciona las capacidades implementadas en el laboratorio Kubernetes con los cuatro controles ISO/IEC 27001:2022 definidos para el Proyecto 6:

- A.8.16
- A.8.9
- A.8.6
- A.5.36

> Este mapeo describe cómo las evidencias técnicas del laboratorio apoyan los controles seleccionados. No constituye por sí solo una certificación ISO/IEC 27001 ni una declaración formal de conformidad organizacional.

---

# A.8.16 — Monitoring activities

## Implementación

El laboratorio utiliza:

- Prometheus para recolección y evaluación de métricas;
- Grafana para visualización;
- Alertmanager para gestión de alertas;
- node-exporter para métricas de nodos;
- kube-state-metrics para estado de objetos Kubernetes;
- ServiceMonitor propio para KubePay;
- 10 reglas de alerta propias identificadas con el prefijo `P6`.

## Evidencia

- dashboards finales;
- captura de Prometheus Targets;
- 10 reglas `P6`;
- `manifests/alerts/proyecto6-alert-rules.yaml`;
- `docs/runbooks.md`;
- evidencias de:
  - `P6KubePayHighDeclineRate`;
  - `P6KubePayReplicasMismatch`;
  - `P6PodCrashLooping`;
- capturas correspondientes en Prometheus y Alertmanager.

## Resultado

El laboratorio puede detectar condiciones anómalas, visualizar su estado y proporcionar procedimientos documentados de atención.

# A.8.9 — Configuration management

## Implementación

La configuración del laboratorio se mantiene mediante:

- manifiestos YAML;
- configuraciones de Kubernetes;
- reglas de Prometheus;
- dashboards exportados;
- cambios controlados de hardening;
- comparaciones Before/After mediante `kube-bench`.

## Remediaciones CIS realizadas

Entre los cambios aplicados se encuentran:

- permisos de `kubelet.service`;
- permisos de `/var/lib/kubelet/config.yaml`;
- `--profiling=false` en kube-apiserver;
- `--profiling=false` en kube-controller-manager;
- `--profiling=false` en kube-scheduler.

## Evidencia

- manifests de KubePay;
- `proyecto6-alert-rules.yaml`;
- reportes kube-bench Before/After;
- dashboard de cumplimiento CIS;
- checkpoints `Pre-CIS` y `Post-CIS-Hardening`.

## Resultado

Las modificaciones de configuración son identificables y se puede demostrar técnicamente el efecto de las remediaciones realizadas.

# A.8.6 — Capacity management

## Implementación

Prometheus y Grafana permiten observar:

- CPU;
- memoria;
- almacenamiento;
- disponibilidad de nodos;
- réplicas de workloads;
- reinicios de contenedores.

## Línea base observada

| Nodo | CPU habitual | Memoria habitual |
|---|---:|---:|
| `cp01` | 24–26% | 79–84% |
| `w01` | 14–16% | 53–55% |
| `w02` | 6–7% | 31–33% |

## Umbrales relacionados

- CPU > 80% durante 5 minutos;
- memoria > 90% durante 5 minutos;
- disco raíz > 85% durante 5 minutos;
- déficit de réplicas de KubePay durante 1 minuto.

## Evidencia

- dashboard `Salud de nodos`;
- dashboard `Capacidad de almacenamiento`;
- `baseline-recursos-nodos.png`;
- reglas:
  - `P6HostHighCpuLoad`;
  - `P6HostMemoryPressure`;
  - `P6DiskSpaceFillingUp`;
  - `P6KubePayReplicasMismatch`.

## Resultado

El laboratorio proporciona visibilidad suficiente para detectar presión de recursos y documentar cuándo una condición supera los límites definidos.

# A.5.36 — Compliance with policies, rules and standards for information security

## Implementación

Para este proyecto se utilizó **CIS Kubernetes Benchmark** como referencia técnica de configuración segura.

`kube-bench` permitió:

1. evaluar el estado inicial;
2. identificar hallazgos;
3. seleccionar controles para remediación;
4. aplicar cambios;
5. ejecutar una evaluación posterior;
6. documentar hallazgos residuales.

## Resultados

Herramienta:

```text
kube-bench 0.16.0
Benchmark: cis-1.12
```

Resultado agregado:

| Evaluación | PASS | FAIL | WARN |
|---|---:|---:|---:|
| Before | 85 | 14 | 52 |
| After | 92 | 7 | 52 |

Reducción de hallazgos `FAIL`:

```text
50%
```

## Evidencia

- reportes Before/After de `cp01`;
- reportes Before/After de `w01`;
- reportes Before/After de `w02`;
- capturas de terminal;
- dashboard `Cumplimiento CIS`;
- registro de las cinco remediaciones;
- lista de hallazgos residuales.

## Resultado

La evidencia permite demostrar una evaluación técnica contra un estándar de configuración de seguridad, registrar desviaciones y comprobar mejoras después de aplicar remediaciones.
